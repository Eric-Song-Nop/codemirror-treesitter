下面是我建议的 **从 PR62 开始的可实现方案**。核心原则是：

> **PR62 先把半成品增量逻辑删干净，恢复一个可理解、可测试的 full-analysis baseline；后续再用 Unit Index 逐步把增量能力加回来。不要在 PR62 里同时删代码、重构、重写增量算法。**

PR62 当前是 draft，标题是 “Add viewport decoration handling to LiveMD core”，但实际 diff 更像“删除 viewport/dirty-range 增量路径”：5 个文件，+33/-775。 当前 `liveMdAnalysisField.update` 在树、文档、active line 或配置变化后直接 `buildLiveMdAnalysis(transaction.state, activeLines)`，也就是回到 full rebuild baseline。 这正好可以作为“先删代码”的起点。

---

# 0. 总目标

不要继续沿着 PR60 那种 dirty boundary 复杂化路线走，也不要上完整 dependency graph 或 query DSL。

最终目标是这个：

```text
Tree-sitter global incremental parse
        ↓
bounded query 找 feature roots
        ↓
LiveMdUnitIndex 记录 rebuild unit
        ↓
changed ranges + old units + new units
        ↓
patch DecorationSet / atomic ranges / fence cache
```

Unit Index 的概念来自前面讨论里已经收敛的结论：它不是依赖图，只是记录“这个 decoration/widget 属于哪个源码范围”；更新时用 changed lines、syntax changed ranges、old units、新 query roots 合成 dirty ranges，再 patch。

不要做：

```text
changed range
→ 向上爬 AST ancestor
→ 命中 list/block_quote/paragraph
→ dirty 整个祖先
```

这个会在整篇 list、整篇 blockquote、nested list、长 paragraph、未闭合 fence 中自然退化成全文。

# 6. PR67：bounded query，仍 full rebuild 或 range rebuild 均可

这是第一个真正必须修的性能点。

当前 PR62 的 `queryLiveMdMatchesFromSource` 完全不传范围，直接：

```ts
queryTreeMatches(tree, source)
```

或 `{ includeNested }`。

底层 wrapper 明明支持 `from` 和 `to`，并会转成 `startIndex` / `endIndex`。

新增：

```ts
type DocRange = { from: number; to: number };

function queryLiveMdMatches(
  tree: Tree,
  ranges: readonly DocRange[],
  includeNested?: boolean,
) {
  return queryLiveMdMatchesFromSource(tree, liveMdQuerySource, ranges, includeNested);
}

function queryLiveMdMatchesFromSource(
  tree: Tree,
  source: TreeSitterQuerySource,
  ranges: readonly DocRange[],
  includeNested?: boolean,
) {
  const matches: LiveMdMatchedQuery[] = [];
  const seen = new Set<string>();

  for (const range of normalizeQueryRanges(tree, ranges)) {
    const queryMatches = queryTreeMatches(tree, source, {
      from: range.from,
      to: range.to,
      includeNested,
    });

    for (const match of queryMatches) {
      if (!matchTouchesRange(match, range)) continue;
      const key = queryMatchKey(match);
      if (seen.has(key)) continue;
      seen.add(key);
      matches.push({ match, range });
    }
  }

  return sortMatches(matches);
}
```

关键：**不要传 `{0,0}`**。Tree-sitter query API 对空范围容易变成无界/无意义查询；normalize 阶段直接丢弃空 range，或者扩成所在行范围。

PR67 测试：

```text
top-of-document dirty range 不能 query 到 EOF
bounded query 仍能捕获跨 range 相交的完整 table/fence/image/link
multiple small ranges 去重正确
```

这一步可以先不做 dirty patch，但 query function 必须可传 range。

# 8. PR69：恢复 patchRangeSet，但基于 UnitIndex

PR69 才真正把 PR60 删除的 patch 能力加回来，但不要恢复旧 dirty boundary 代码。

update 逻辑：

```ts
update(previous, transaction) {
  const nextTree = syntaxTree(transaction.state);
  const nextActiveLines = getActiveLines(transaction.state);

  if (mustFullRebuild(previous, transaction, nextTree, nextActiveLines)) {
    return buildLiveMdAnalysis(transaction.state, nextActiveLines);
  }

  const mappedDecorations = transaction.docChanged
    ? previous.decorations.map(transaction.changes)
    : previous.decorations;

  const mappedAtomicRanges = transaction.docChanged
    ? previous.atomicRanges.map(transaction.changes)
    : previous.atomicRanges;

  const plan = createLiveMdDirtyPlan({
    previous,
    transaction,
    activeLines: nextActiveLines,
  });

  if (!plan.dirtyRanges.length) {
    return {
      ...previous,
      activeLines: nextActiveLines,
      decorations: mappedDecorations,
      atomicRanges: mappedAtomicRanges,
      unitIndex: previous.unitIndex.map(transaction.changes, transaction.state),
      tree: nextTree,
    };
  }

  if (plan.fallbackToFull) {
    return buildLiveMdAnalysis(transaction.state, nextActiveLines);
  }

  const dirtyBuild = buildLiveMdAnalysis(transaction.state, nextActiveLines, {
    ranges: plan.queryRanges,
  });

  return {
    activeLines: nextActiveLines,
    decorations: patchRangeSet(
      mappedDecorations,
      plan.dirtyRanges,
      rangeSetRanges(dirtyBuild.decorations, transaction.state.doc.length),
    ),
    atomicRanges: patchRangeSet(
      mappedAtomicRanges,
      plan.dirtyRanges,
      rangeSetRanges(dirtyBuild.atomicRanges, transaction.state.doc.length),
    ),
    codeFenceHighlightTrees: patchCodeFenceTrees(previous, transaction, dirtyBuild, plan),
    unitIndex: reconcileUnitIndex(mappedOldIndex, plan, dirtyBuild.unitIndex),
    tree: nextTree,
  };
}
```

full rebuild 条件先保守：

```text
config changed
markdownFeatures changed
image resolver changed
link base URL changed
code fence language map changed
syntax tree unavailable
dirty ranges > visible/full threshold
```

注意：PR62 现在删除了 `codeFenceLanguages` 缓存字段；PR69 可以不用恢复那个字段，只在 configChanged 时 full rebuild。

PR69 测试恢复 PR62 删掉的两个关键测试：

```text
preserves unchanged widget instances across unrelated text edits
does not reparse unchanged code fences after unrelated edits
```

PR62 删除了这两个测试。 PR69 必须以 UnitIndex 新模型恢复它们。

# 10. PR71：code fence-local incremental parse

```ts
type CodeFenceParseEntry = {

  parserIdentity: string;

  contentTo: number;
```

```ts
const localChanges = mapGlobalChangesToFenceContent(transaction.changes, oldContentFrom);
```

# 16. 最小设计约束

后续所有 PR 都遵守这几个约束：

1. **Tree-sitter global parse 是 source of syntax truth。** 不另写 block-local Markdown parser。
2. **Query 只找 feature root。** 继续用 `@feature` / `liveMd.kind` / `@table` / `@codeFence` / `@image` / `@latex`，不发明复杂 query DSL。
3. **Dirty 由 old units + new units 决定。** 不做祖先无限扩张。
4. **特殊性集中到 unit rules。** 不散落在 `if node.name === ...` 里。
5. **测试先看 trace，再看 DOM。** 大文档增量必须靠 dirty/query/build/parse 计数证明，Playwright/CDP 只证明真实交互和闪烁。

一句话：**PR62 先把错误的增量路径删成一个干净 baseline；后面用 Unit Index 把增量能力一点点加回来，而不是把 PR60 的 dirty boundary 修修补补。**

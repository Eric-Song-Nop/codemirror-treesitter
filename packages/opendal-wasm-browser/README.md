# @codemirror-treesitter/opendal-wasm-browser

Experimental package for a browser-first OpenDAL WASM wrapper.

The goal is to prove whether an OpenDAL `wasm32-unknown-unknown` build can power
cloud-backed Markdown workspaces in `apps/local-md-workspace` without a server
gateway.

## Current Status

- Phase 1 wrapper spike is implemented for S3-compatible storage.
- `src/lib.rs` exposes a narrow `wasm-bindgen` class around OpenDAL.
- `src/index.ts` provides the TypeScript-facing loader and normalized API.
- `pkg/` is generated by `wasm-pack` and ignored by git.
- `dist/` is generated by `vp pack` and ignored by the repository root.
- Real browser provider smoke tests are still pending.

## Scope

This package will start with the smallest browser-compatible OpenDAL service
surface needed by `apps/local-md-workspace`:

- list Markdown files under a root prefix
- read and write Markdown file text
- create, delete, and rename Markdown files
- expose backend capability information for operations such as native rename

The first implementation target is S3-compatible object storage because OpenDAL
has existing WASM tracking for S3 and S3-compatible storage covers AWS S3,
Cloudflare R2, MinIO, and several other providers.

## API

```ts
import { createOpendalBrowserOperator } from "@codemirror-treesitter/opendal-wasm-browser";

let operator = await createOpendalBrowserOperator({
  provider: "s3",
  endpoint: "https://example-r2-or-s3-endpoint",
  bucket: "markdown",
  region: "auto",
  root: "workspace",
  accessKeyId: "...",
  secretAccessKey: "...",
});

await operator.writeText("smoke.md", "# Smoke\n");
let text = await operator.readText("smoke.md");
```

The wrapper currently exposes:

- `capabilities()`
- `list(prefix)`
- `readText(path)`
- `writeText(path, value)`
- `delete(path)`
- `rename(from, to)`
- `stat(path)`

`rename` uses OpenDAL native rename when the backend supports it. Otherwise it
falls back to copy/delete when copy is available.

## Build

Generate the browser WASM package:

```bash
vp run @codemirror-treesitter/opendal-wasm-browser#build:wasm
```

Build the TypeScript wrapper:

```bash
vp run @codemirror-treesitter/opendal-wasm-browser#build:ts
```

The generated TypeScript wrapper dynamically imports
`pkg/opendal_wasm_browser.js` by default. Callers can override
`generatedModuleUrl` or `wasmModuleUrl` when a bundler or deployment path needs
explicit asset URLs.

## Smoke Fixture

`smoke/index.html` and `smoke/main.ts` provide a small Vite browser fixture.
Before opening it, store a JSON config in local storage under
`OPENDAL_BROWSER_SMOKE_CONFIG`.

Example shape:

```json
{
  "provider": "s3",
  "endpoint": "https://example-r2-or-s3-endpoint",
  "bucket": "markdown",
  "region": "auto",
  "root": "workspace",
  "accessKeyId": "...",
  "secretAccessKey": "..."
}
```

Cloud storage CORS must allow the browser requests. This wrapper cannot bypass
same-origin policy or make unsafe frontend credentials safe.

## Validation

Package-local validation:

```bash
vp check packages/opendal-wasm-browser
RUSTC="$(rustup which rustc)" rustup run stable cargo check --manifest-path packages/opendal-wasm-browser/Cargo.toml --target wasm32-unknown-unknown
vp pack
```

Repository-level validation can be checked with:

```bash
vp check
```

Provider validation is not part of default CI yet because it requires cloud
credentials and provider-specific CORS setup.

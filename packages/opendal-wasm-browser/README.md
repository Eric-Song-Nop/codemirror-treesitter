# @codemirror-treesitter/opendal-wasm-browser

Experimental package for a browser-first OpenDAL WASM wrapper.

It provides the exact object-operation boundary used by both a user-selected
browser directory and cloud-backed Markdown workspaces in
`apps/local-md-workspace` without a storage gateway.

## Current Status

- The exact browser operator and BrowserLocal OpenDAL service are implemented.
- Dropbox, Google Drive, OneDrive, and S3-compatible providers are wired in the
  wrapper API.
- `src/browser_local.rs` implements OpenDAL `raw::Access` over an injected
  `FileSystemDirectoryHandle`; it does not use OPFS or a second content API.
- `src/lib.rs` exposes the narrow `wasm-bindgen` boundary around OpenDAL.
- `src/index.ts` validates generated values and exposes one
  `OpendalExactBrowserOperator` for every source.
- Dropbox reads and conditional writes use its browser REST API to expose the
  revision semantics that OpenDAL 0.57 does not currently surface.
- `pkg/` is generated by `wasm-pack` and ignored by git.
- `dist/` is generated by `vp pack` and ignored by the repository root.
- Browser and credential-gated smoke entry points exist; real provider runs are
  still pending credentials and CORS/provider setup.

## Scope

This package exposes the smallest browser-compatible OpenDAL service surface
needed by `apps/local-md-workspace`:

- list Markdown files under a root prefix
- read and write Markdown file text
- create missing directories, and delete or rename Markdown files
- expose backend capability information for operations such as native rename

The first user-facing implementation target is Dropbox using a pure frontend
OAuth code flow with PKCE and short-lived access tokens. The OAuth flow lives in
`apps/local-md-workspace`; this wrapper only receives the resulting
`accessToken`.

OneDrive is available as the next cloud-backend foundation. The browser-facing
API currently accepts a short-lived Microsoft Graph access token, exposes
metadata such as ETag/version values, and supports conditional writes through
OpenDAL's `write_with_if_match` capability when the provider advertises it.
OneDrive OAuth/UI wiring belongs in `apps/local-md-workspace`, not this package.

Google Drive is also available as a backend foundation through OpenDAL's
`gdrive` service. It accepts a short-lived Google Drive API access token and
supports the same narrow workspace operation set. OpenDAL's Google Drive service
does not currently advertise native conditional writes, so `{ ifMatch }` is not
forwarded for Google Drive even though the shared wrapper API accepts it.
The local workspace app requests `https://www.googleapis.com/auth/drive.file` so
Google Drive access stays limited to files and folders created or opened through
the app. Google Drive OAuth/UI wiring belongs in `apps/local-md-workspace`, not
this package.

S3-compatible object storage remains available as a secondary provider track for
MinIO, Cloudflare R2, AWS S3, and similar services.

## Exact API

```ts
import { openOpendalBrowserOperator } from "@codemirror-treesitter/opendal-wasm-browser";

let operator = await openOpendalBrowserOperator({
  kind: "dropbox",
  accessToken: "...",
  root: "workspace",
});

let created = await operator.write({
  bytes: new TextEncoder().encode("# Smoke\n"),
  condition: { kind: "if-not-exists" },
  path: "smoke.md",
});
let snapshot = await operator.read("smoke.md");
if (snapshot.metadataBinding != "same-read" || !snapshot.metadata.version) {
  throw new Error("Dropbox did not return a source revision");
}
await operator.write({
  bytes: new TextEncoder().encode("# Updated\n"),
  condition: { kind: "if-version", version: snapshot.metadata.version },
  path: "smoke.md",
});

await operator.createDirectory("notes");
```

BrowserLocal uses the same operator contract:

```ts
let rootHandle = await showDirectoryPicker({ mode: "readwrite" });
let localOperator = await openOpendalBrowserOperator({
  kind: "browser-local",
  rootHandle,
});
```

The exact operator exposes:

- `info` with normalized capabilities, scheme, and root
- `stat(path)`
- `list(path)`
- `read(path)` with explicit metadata binding
- `write(request)` with one explicit condition and a write receipt
- `createDirectory(path)`
- `delete(request)` with applied, partial, or unknown outcomes
- `rename(request)` with applied, partial, or unknown outcomes
- `dispose()` to release the underlying WASM operator

The older `createOpendalBrowserOperator` text/byte facade remains exported for
compatibility but is deprecated. Product code uses the exact operator through
the application object-store layer.

`createDirectory` normalizes directory paths and delegates to OpenDAL's recursive
`create_dir` behavior when the backend advertises `nativeCreateDir`.

`rename` uses OpenDAL native rename when the backend supports it. Otherwise it
falls back to verified copy/delete when the required primitives are available.

## Source Layout

- `src/browser_local.rs`: BrowserLocal OpenDAL service over File System Access.
- `src/lib.rs`: Rust `wasm-bindgen` wrapper around BrowserLocal and cloud OpenDAL
  operators.
- `src/index.ts`: TypeScript loader, config normalization, generated WASM
  module initialization, and normalized operator facade.
- `pkg/`: generated `wasm-pack` output consumed by the TypeScript wrapper and
  local workspace app.
- `smoke/browser-local.*`: interactive BrowserLocal read/write/list fixture.
- `smoke/*`: cloud browser fixture and credential-gated Dropbox validation
  helpers.

## Build

Build the browser WASM package and TypeScript wrapper:

```bash
vp run @codemirror-treesitter/opendal-wasm-browser#build
```

The package build runs the lower-level WASM and TypeScript builds in order.
Those tasks can still be run individually:

```bash
vp run @codemirror-treesitter/opendal-wasm-browser#build:wasm
vp run @codemirror-treesitter/opendal-wasm-browser#build:ts
```

The TypeScript wrapper dynamically imports `pkg/opendal_wasm_browser.js` by
default. Browser apps that need explicit bundler asset URLs should use the
package-owned runtime contract:

```ts
import {
  defaultOpendalBrowserRuntimeOptions,
  openOpendalBrowserOperator,
} from "@codemirror-treesitter/opendal-wasm-browser";

let operator = await openOpendalBrowserOperator(source, defaultOpendalBrowserRuntimeOptions());
```

Callers can still override `generatedModuleUrl` or `wasmModuleUrl` when a
deployment path needs custom asset URLs.

## Smoke Fixture

`smoke/index.html` and `smoke/main.ts` provide a small Vite browser fixture.
Before opening it, store a JSON config in local storage under
`OPENDAL_BROWSER_SMOKE_CONFIG`.

Example shape:

```json
{
  "provider": "s3",
  "endpoint": "https://example-r2-or-s3-endpoint",
  "bucket": "markdown",
  "region": "auto",
  "root": "workspace",
  "accessKeyId": "...",
  "secretAccessKey": "..."
}
```

Cloud storage CORS must allow the browser requests. This wrapper cannot bypass
same-origin policy or make unsafe frontend credentials safe.

Dropbox smoke config uses a short-lived access token:

```json
{
  "provider": "dropbox",
  "root": "workspace",
  "accessToken": "..."
}
```

Google Drive smoke config uses a short-lived Google Drive API access token:

```json
{
  "provider": "gdrive",
  "root": "workspace",
  "accessToken": "..."
}
```

OneDrive smoke config also uses a short-lived Microsoft Graph access token:

```json
{
  "provider": "onedrive",
  "root": "workspace",
  "accessToken": "..."
}
```

Clicking the fixture runs the full narrow workspace operation set:

- `list("")`
- `writeText("opendal-browser-smoke-....md", value)`
- `readText(...)`
- `rename(..., "...-renamed.md")`
- `stat(...)`
- `delete(...)`

There is also a credential-gated Dropbox smoke task for local validation after
building `pkg/`:

```bash
OPENDAL_DROPBOX_ACCESS_TOKEN="..." \
  vp run @codemirror-treesitter/opendal-wasm-browser#smoke:dropbox
```

For local validation, get that short-lived token through PKCE instead of the
Dropbox App Console:

```bash
OPENDAL_DROPBOX_APP_KEY="your-public-app-key" \
  vp run @codemirror-treesitter/opendal-wasm-browser#auth:dropbox-token
```

The helper prints a Dropbox OAuth URL, asks you to paste the authorization code
shown after approval, and then prints `export` commands for
`OPENDAL_DROPBOX_ACCESS_TOKEN` and `LOCAL_MD_WORKSPACE_DROPBOX_ACCESS_TOKEN`.
It uses `token_access_type=online`, does not use a client secret, and does not
request a refresh token. This is only for developer smoke validation; app users
should use the normal in-app Dropbox OAuth login.

For the local Markdown workspace app OAuth flow, configure the public Dropbox
app key in `apps/local-md-workspace/.env.local`:

```env
VITE_DROPBOX_APP_KEY="your-public-app-key"
VITE_DROPBOX_REDIRECT_URI="http://localhost:5173"
```

`VITE_DROPBOX_REDIRECT_URI` is optional, but when it is set the exact value must
also be registered in the Dropbox App Console Redirect URIs. Without it, the app
derives the redirect URI from the current page.

If the Dropbox app has a local redirect URI registered, the helper can also run
a temporary callback server and complete the code capture automatically:

```bash
OPENDAL_DROPBOX_APP_KEY="your-public-app-key" \
  vp run @codemirror-treesitter/opendal-wasm-browser#auth:dropbox-token -- \
  --redirect-uri "http://127.0.0.1:53682/dropbox-oauth" \
  --open
```

Optional variables:

- `OPENDAL_DROPBOX_APP_KEY`: public Dropbox app key used by
  `auth:dropbox-token`.
- `OPENDAL_DROPBOX_REDIRECT_URI`: optional redirect URI for the token helper.
- `OPENDAL_DROPBOX_SCOPES`: optional scope override for `auth:dropbox-token`.
- `OPENDAL_DROPBOX_ROOT`: Dropbox root passed to the OpenDAL operator.
- `OPENDAL_DROPBOX_SMOKE_PREFIX`: file-name prefix for the temporary smoke file.

The task exits successfully without doing provider work when
`OPENDAL_DROPBOX_ACCESS_TOKEN` is not set, so it can remain available without
making default validation depend on Dropbox credentials.

To run both real Dropbox validation paths after exporting a token, use:

```bash
vp run @codemirror-treesitter/opendal-wasm-browser#validate:dropbox
```

This starts the local Markdown workspace dev server on an available local port,
runs the app UI Dropbox smoke with the same token, runs the wrapper Dropbox
operation smoke, and then stops the dev server. It skips cleanly when no token is
set; pass `-- --require-token` when you want missing credentials to fail the
command.

## Validation

Package-local validation:

```bash
vp run @codemirror-treesitter/opendal-wasm-browser#test
vp run @codemirror-treesitter/opendal-wasm-browser#check:wasm
vp run @codemirror-treesitter/opendal-wasm-browser#build
vp run @codemirror-treesitter/opendal-wasm-browser#auth:dropbox-token
vp run @codemirror-treesitter/opendal-wasm-browser#validate:dropbox
vp run @codemirror-treesitter/opendal-wasm-browser#smoke:dropbox
```

The package `test` task runs the host Rust unit tests before the TypeScript
Vitest suite. The `check:wasm` task separately verifies the wasm32 target.

Repository-level validation can be checked with:

```bash
vp check
```

Provider validation is not part of default CI yet because it requires cloud
credentials and provider-specific CORS setup.
